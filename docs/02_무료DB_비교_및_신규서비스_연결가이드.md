# 무료티어 DB 선택 & 연결 가이드 (2026) — 신규 솔루션 설계용

> 용도: 새 서비스/솔루션을 구상할 때 **"엑셀 업로드 → 테이블 자동 구축 → 조회·편집 관리"** 가 가능한 무료티어 DB를 고르고, 연결하는 방법을 정리한 범용 레퍼런스.
> 조사 기준일: 2026년 7월 · 무료티어 정책은 자주 바뀌므로 도입 직전 각 공식 pricing 페이지 재확인 권장.

---

## 1. 결론 먼저 (요구사항별 추천)

| 원하는 것 | 추천 | 한 줄 이유 |
|-----------|------|-----------|
| **DB가 직접** 엑셀→테이블 만들고 편집 UI까지 제공 (코드 최소) | **NocoDB (셀프호스트)** | 무료·무제한, 엑셀 업로드 시 시트별 테이블 자동 생성, 스프레드시트 UI 내장 |
| 위와 같지만 **설치 없이 클라우드로** 바로 | **Baserow** (무료 클라우드 3,000행) 또는 **Airtable**(1,000행) | 회원가입만 하면 끝, 엑셀 임포트 내장 |
| **앱을 직접 만들고** 진짜 DB만 붙이기 | **Supabase** 또는 **Neon** | 순수 Postgres, pandas `to_sql`로 테이블 자동 구축 |
| 유휴로 방치돼도 **안 멈추는** DB가 필요 | **Neon** | Supabase는 7일 유휴 시 일시정지, Neon은 scale-to-zero라 안 멈춤 |

> **가장 실용적인 조합:** NocoDB/Baserow를 "엑셀→테이블 관리 도구"로 쓰고,
> **같은 Postgres를 앱이 읽게** 하면 — 관리 UI는 공짜로 얻고 CRUD 코드는 안 짜도 된다. (→ 5-3)

## 2. 두 가지 카테고리를 구분하라

무료 DB는 성격이 완전히 다른 두 종류가 있고, 요구사항("엑셀 올리면 테이블이 만들어지고 관리")에 대한 답이 다르다.

### (A) 순수 DBaaS — "DB 엔진"만 제공
Supabase, Neon, Turso 등. **테이블 관리 UI는 최소**(SQL 위주). "엑셀 업로드→테이블 구축"은 **앱이 직접 구현**해야 함 (pandas `to_sql` 한 줄이면 엑셀 컬럼 구조 그대로 테이블 자동 생성). → 앱을 직접 만드는 시나리오.

### (B) 스프레드시트-DB 하이브리드 — "관리 도구 + DB"를 함께 제공
NocoDB, Baserow, Teable, Airtable, Grist. **엑셀 업로드 → 테이블 자동 생성 → 엑셀 같은 편집 UI**가 **기본 내장**. 코드 없이 바로 "관리"가 됨. REST API로 외부 앱이 읽어갈 수 있음.

요구사항 문장 그대로("엑셀 업로드로 테이블 구축·관리")에 **가장 근접한 건 (B) 카테고리**다.

## 3. 무료티어 상세 비교표 (2026)

### (A) 순수 DBaaS

| DB | 엔진 | 무료 용량 | 프로젝트 수 | 유휴 정책 | 엑셀/CSV 임포트 UI | 비고 |
|----|------|-----------|-------------|-----------|--------------------|------|
| **Supabase** | Postgres | **500MB** DB + 1GB 파일 | 2개 | **7일 유휴 시 일시정지** | Table Editor에서 **CSV 임포트**(≤100MB) | Auth·Storage·Realtime 올인원 |
| **Neon** | Postgres | **0.5GB/프로젝트** | **최대 100개** | scale-to-zero (**안 멈춤**) | 내장 UI 없음(psql/`\copy`/앱) | 브랜칭 지원, 순수 Postgres, 유휴에 강함 |
| **Turso** | SQLite/libSQL | **5GB**, 월 5억 행 읽기 | 다수 | 안 멈춤 | 내장 UI 없음 | 엣지 저지연 읽기, SQLite 계열 |

> **PlanetScale(MySQL)은 2024년 4월 무료티어 폐지.** Railway도 무료 상시 플랜 없음(크레딧/트라이얼). 무료 목적이면 후보에서 제외.

### (B) 스프레드시트-DB 하이브리드 (엑셀→테이블 관리 내장)

| 도구 | 백엔드 | 무료(클라우드) | 셀프호스트 | 엑셀 임포트 | 외부 연동 |
|------|--------|----------------|------------|-------------|-----------|
| **NocoDB** | Postgres/MySQL/SQLite 위에 얹음 | 클라우드 무료 5만 행/월 10만 API/20GB | **완전 무제한 무료** (행·유저·API 제한 없음) | **엑셀/CSV/JSON → 테이블 자동 생성** (시트별로 테이블 분리) | REST API, 기존 DB에 직접 연결 가능 |
| **Baserow** | 자체(Django+Postgres) | 무료 **3,000행/워크스페이스** | **무제한 무료** | 엑셀/CSV 임포트 → 필드 자동 생성 | REST API, 웹훅 |
| **Teable** | Postgres 기반 | 커뮤니티/무료 **매우 제한적**(약 100행·2유저) | 제한 있음 | 엑셀 임포트 | REST API. 신생·빠르지만 무료 한도가 가장 빡빡 |
| **Airtable** | 자체(클라우드 전용) | **1,000 레코드/base**(테이블 합산), 1GB 첨부 | 불가(SaaS) | 엑셀/CSV 임포트 | REST API. 설치 0, 대신 행 한도 작음 |

**요약 판단**
- **데이터 양이 실무 규모(수천~수만 행)** 이고 공짜여야 함 → **NocoDB 셀프호스트**(무제한) 또는 **Baserow 셀프호스트**.
- **설치가 부담**, 소량이면 됨 → **Baserow 클라우드(3,000행)** > Airtable(1,000행).
- **Teable**은 아이디어는 좋으나(Postgres·빠름) 무료 한도가 현재 가장 작아 소규모 검증용에만.

## 4. 각 후보별 "엑셀→테이블 관리" 실제 흐름

**NocoDB (셀프호스트, 권장):**
1. `docker run -d -p 8080:8080 nocodb/nocodb` (또는 docker-compose로 Postgres 연결)
2. 브라우저 접속 → 프로젝트 생성 → **"Import → Microsoft Excel"** → 파일 선택
3. 시트마다 테이블 자동 생성, 컬럼 타입 자동 추론 → **스프레드시트 UI에서 즉시 편집**
4. 외부 앱은 REST API(`/api/v2/tables/{id}/records`) 또는 **NocoDB가 얹혀있는 Postgres**를 직접 조회

**Baserow (클라우드, 설치 0):**
1. baserow.io 가입 → 워크스페이스 생성
2. **"Import file → Excel"** → 테이블 자동 생성
3. 그리드에서 편집, REST API 토큰 발급해 외부 연동

**Airtable (가장 간단, 소량):**
1. airtable.com 가입 → Base 생성 → **"Add a table → Import a spreadsheet"**
2. 편집, `api.airtable.com`으로 연동 (Personal Access Token)

## 5. 신규 서비스에서 무료 DB 연결하는 법 (코드)

새 서비스(Streamlit/FastAPI 등)를 만들 때 각 DB에 붙이는 최소 코드. **연결 문자열/키만 바뀌고 나머지는 거의 동일**하다. (예시 테이블명은 `my_table`.)

### 5-1. 순수 Postgres (Supabase · Neon 공통) — Streamlit `st.connection` 방식

가장 Streamlit-친화적. `SQLAlchemy` + `psycopg2` 필요.

`.streamlit/secrets.toml`:
```toml
[connections.db]
url = "postgresql://<user>:<password>@<host>:5432/<database>"
# Supabase: Project Settings → Database → Connection string(Session pooler)
# Neon:     대시보드 → Connection Details → Connection string
```

앱 코드:
```python
import streamlit as st
import pandas as pd

conn = st.connection("db", type="sql")

# 읽기 (쿼리 결과 캐시 지원)
df = conn.query("SELECT * FROM my_table", ttl="10m")

# 쓰기 (엑셀 업로드 → 테이블 자동 구축)
up = st.file_uploader("엑셀", type="xlsx")
if up:
    new = pd.read_excel(up)
    with conn.session as s:
        # if_exists="replace" → DROP+CREATE, 엑셀 컬럼 구조로 테이블 자동 생성
        new.to_sql("my_table", s.connection(), if_exists="replace", index=False)
        s.commit()
    st.success(f"{len(new):,}행 저장 — 테이블 자동 생성됨")
```

> **핵심:** `df.to_sql(name, engine, if_exists="replace")` 가 **수동 `CREATE TABLE` 없이 엑셀 스키마 그대로 테이블을 만든다.** 이것이 "엑셀 업로드로 테이블 구축"의 코드 실체다.

**프레임워크 무관 버전(순수 SQLAlchemy — FastAPI 등):**
```python
from sqlalchemy import create_engine
import pandas as pd

engine = create_engine(DATABASE_URL, pool_pre_ping=True)   # pause 복구
pd.read_excel("file.xlsx").to_sql("my_table", engine, if_exists="replace", index=False)
df = pd.read_sql('SELECT * FROM my_table', engine)
```

### 5-2. Supabase 파이썬 클라이언트(REST) 방식 — 참고

Auth/Storage/Realtime까지 함께 쓸 때. **테이블은 미리 만들어져 있어야 함**(코드로 DDL 불가).
```python
from supabase import create_client
sb = create_client(SUPABASE_URL, SUPABASE_KEY)          # KEY = anon key
sb.table("my_table").upsert(df.to_dict("records")).execute()   # 쓰기
rows = sb.table("my_table").select("*").execute().data          # 읽기
```

### 5-3. NocoDB / Baserow (REST API) 방식 — "관리 UI는 그 도구에서, 조회는 내 앱에서"

관리(엑셀 임포트·편집)는 NocoDB/Baserow 웹 UI에서 하고, 앱은 **읽기만** 한다.

```toml
NOCODB_URL   = "http://<호스트>:8080"
NOCODB_TOKEN = "<xc-token>"          # NocoDB: Account → Tokens
NOCODB_TABLE = "<table_id>"
```

```python
import requests, pandas as pd

def load_nocodb():
    r = requests.get(
        f"{NOCODB_URL}/api/v2/tables/{NOCODB_TABLE}/records",
        headers={"xc-token": NOCODB_TOKEN},
        params={"limit": 1000},
    )
    r.raise_for_status()
    return pd.DataFrame(r.json()["list"])
```

> **또는 더 단순하게:** NocoDB를 **Postgres 위에** 띄웠다면, 그 Postgres 연결 문자열로 5-1 코드를 그대로 쓰면 된다. NocoDB에서 편집한 내용이 같은 테이블이므로 앱이 바로 읽는다. → **관리 UI(공짜) + SQL 조회**를 동시에 얻는 최적 구성.

### 5-4. Neon 전용 팁

- 대시보드 → **Connection Details → "Connection string"** 복사 (`?sslmode=require` 포함).
- `to_sql`/`read_sql` 코드는 Supabase와 100% 동일.
- **유휴에도 안 멈춤** — 방치되기 쉬운 사내 대시보드/저트래픽 서비스에 특히 적합.
- 프로젝트를 최대 100개까지 무료로 만들 수 있어, 서비스마다 DB를 분리하기 좋다.

## 6. 배포 시 시크릿 설정

로컬 `.streamlit/secrets.toml`(또는 `.env`)은 저장소에 커밋하지 말 것(`.gitignore` 처리). 배포처에서 별도 등록:

- **Streamlit Community Cloud:** 앱 → **Settings → Secrets** 에 `secrets.toml` 내용 그대로 붙여넣기.
- **Docker/서버:** 환경변수 `DATABASE_URL` 등으로 주입. 코드는 `st.secrets.get("DATABASE_URL", os.getenv("DATABASE_URL"))` 폴백 패턴 권장.

## 7. 신규 솔루션 선택 결정 가이드

```
Q1. 엑셀→테이블+편집을 "코드 없이" DB/도구가 알아서 해줬으면?
    ├─ 예 → Q2
    └─ 아니오(앱을 직접 만들 것) → Q3

Q2. 서버 설치(Docker) 가능?
    ├─ 예 → NocoDB 셀프호스트 (무제한 무료)  ← 데이터 많을 때 최선
    └─ 아니오(클라우드로 바로) → 데이터 양?
            ├─ 수천 행 → Baserow 클라우드(3,000행)
            └─ 수백 행 → Airtable(1,000행)

Q3. 서비스가 유휴로 방치될 수 있나?
    ├─ 예(가끔 접속) → Neon (scale-to-zero, 안 멈춤)
    └─ 아니오(꾸준히 트래픽) + Auth/Storage도 필요 → Supabase (올인원)
```

**공통 원칙**
- 순수 DB 경로(Supabase/Neon)는 **연결 문자열만 다르고 코드는 동일** → 나중에 갈아타기 쉽다. Neon으로 시작해도 Supabase 이전 비용이 거의 없다.
- 관리 UI가 핵심이면 **NocoDB를 Postgres 위에** 올려서 "관리 UI + 순수 SQL 조회"를 동시에 챙기는 구성이 가장 유연하다.
- 무료 용량 한계(예: Supabase 500MB 초과 시 read-only 전환)를 설계 초기에 감안하고, 초과 시 이전 경로(Neon 등)를 미리 정해둔다.
